# 検針管理機能 開発計画（FileMaker検針アプリの移植）

Oct 20, 2026 · @栄和共有

## 結論と進め方

**計画を確定しました（2026-10-20）。** Q1〜Q12 の回答と、FileMaker「検針記録」のテーブル5つ・出力ファイル2つ・請求書Excel・画面18枚を検証した結果を反映しています。備品と同じ作り（Supabase の新テーブル＋`worker/lib/meter.js`＋`/meter` 配下の画面）で、5つのフェーズに分けて FileMaker と並行運用しながら移植します。

- **このアプリの役割は FileMaker の置き換えです。** 検針値を記録し、今と同じ「検針データ\_yyyy年mm月分.xlsx」「修理データ\_yyyy年mm月分.xlsx」を出します。請求額の計算とテナント内の振り分けは、今までどおり後続の請求書Excelで行います（Q3・Q4）
- **撮影は方式Bで確定です。** iPhone の標準カメラで撮った写真をまとめて取り込むと、写真に写ったバーコード（Code39、例 `*11-A*`）からメータを判定し、テナントまで自動で割り当てます
- **実データの規模**: メータ69台（うち撤去済み4）、毎月の検針は約56件、空調室内機96台、過去の検針値は2019年4月から5,181件です。写真以外は全件移行します
- **費用はかかりません。** 写真を縮小し、2年を過ぎたら自動で削除すると、保存量は約30MBで頭打ちになり、Supabase の無料枠1GBに収まります（7章）
- **先に決めていただきたいことが2つあります**（9-1 の D1・D2）。出力ファイルの計算列を今と同じに出すかと、提出メールをどのアドレスから送るかです
- コード変更・本番反映は、この2点への回答をいただいてから Phase 1 に着手します

## 1. 目的と範囲

FileMaker「検針記録」アプリ（Mac 版と iPhone の「検針記録Mobile」）でやっていることを、このアプリで完結させて FileMaker を止めるのが目的です。対象は備後町コイズミビルの全テナント（空室・共用エリアを含む）です。

**範囲に含むもの**

- 電気メータ（月初第1営業日）と、さくらのガス・水道メータ（月の半ば。翌月度分として記録）の写真と値
- 外調機メータ（メータ番号 00。オフピーク・ピークの2値、小数第2位まで）
- 空調集中コントローラの按分CSVの取込と、室内機→メータの紐付け
- 打ち間違いの検証（音声読み上げ、前月比の強調、写真と値の見比べ、撮り忘れの確認）
- 出力: 検針データ・修理データの xlsx、メータ写真一覧の印刷、ガス・水道お渡し票、提出メールとガス検針票メールの下書き（添付付き）
- マスタ: テナント（備品と共有）、貸室・メータ、空調機の紐付け、定数（外調係数40・面積・メール宛先）
- 過去データの移行（検針値5,181件・空調データ8,256件。写真は移行しない）

**含めないもの**

- 請求額の計算、テナント内の振り分け、空室を除いた按分（後続の請求書Excelで行う。Q3・Q4）
- 写真からのメータ値の自動読み取り（AI。費用がかかり、廃棄物の手書き読取で失敗した経緯もあるため）
- 大昭和紙工産業様向けの年間検針実績表（データはそろうので後から足せます）
- メールの自動送信（下書きまで作り、送信は手で。Q7）

## 2. 現行業務と新しい流れ

FileMaker の「メータ検針メインメニュー」の並びどおりに、月の作業を移植後の画面へ対応させたものです。検針月度は「請求する月」で、例えば 2026年10月度は 10/1 に検針し、9/1〜9/30 の使用分を表します。

| いつ | 現行（FileMaker のボタン） | 移植後 |
| --- | --- | --- |
| N月の半ば | ガス・水道を撮影 →「ガス・水道お渡し票」を印刷 →「ガス検針表の送付」 | 同じ写真取込（N+1月度として記録）、お渡し票PDF、検針票のスキャンPDFを添付したメール下書き |
| N+1月の第1営業日 | iPhoneの検針アプリで撮影 → サーバへアップロード | iPhone 標準カメラで撮影 →「写真の取込」でまとめて送信。バーコードで自動割当 |
| 同上 | 空調データをUSBへ → 指定フォルダにコピー →「空調データの取込」 | 「空調データ」画面にCSVをドラッグ。フォルダ指定は不要 |
| 同上 | 「一覧〜メータ値入力」（♩で読み上げ） | 「検針一覧」→「値の入力」。Enter で読み上げて次のメータへ |
| 同上 | 「過不足の確認」 | 取込画面と一覧に、写真の無いメータ・割り当てていない写真を常に表示 |
| 同上 | 「メータ写真の印刷」（1ページ8枚） | 写真一覧PDF（同じ配置、値を黄色で重ねる） |
| 同上 | 「Excel出力：検針＆空調」「Excel出力：修理データ」 | 同じ名前・同じ列の xlsx をダウンロード |
| 同上 | 「報告」（Mac のメールで宛先・件名・添付2つ入りの画面） | 提出メールの下書きを作る（方式は D2） |
| その後 | 小泉産業様側で請求書Excelに貼り付けて請求書作成 | 変更なし |

後続の請求書Excel「新請求書サマリー」は、「当月検針データ」「当月修理データ」シートに貼られた値を**列の位置（何列目か）で**参照しています（サマリーシート5行目の列番号）。このため出力ファイルは列の順番まで今と同じにします。

## 3. 全体方針と技術上の判断

新しい仕組みは持ち込まず、備品・廃棄物・ビルメンと同じ作り方で足します。

### 3-1. 撮影の方式（B で確定）

**回答（Q1）: B。まとめてアップロードしてテナントを順次自動判定する。** このアプリは Service Worker にキャッシュ処理を持たせない鉄則（HANDOFF 3章）がありオフラインでは動かないため、地下ではアプリを使わずに済むこの方式にします。検討した3方式の比較は次のとおりです。

| 方式 | 地下での操作 | バーコード | 圧外での安全性 | 開発量 | 費用 |
| --- | --- | --- | --- | --- | --- |
| **B. 標準カメラ＋事務所でまとめて取込（推奨）** | iPhone の「カメラ」アプリで、バーコードとメータが写るように撮るだけ | 取込時に写真から自動で読む。読めない写真は一覧から手で割り当て | 最も高い（アプリを使わない） | 小 | 0円 |
| A. アプリ内で撮影し端末に一時保存 | 事務所で画面を開いてから地下へ。撮るたびに端末内（IndexedDB）へ保存し、戻ってから送信 | 撮影直後に読んでその場でメータ名を表示 | 中（途中でアプリが再読み込みされると圧外では開けない） | 中 | 0円 |
| C. 検針専用ページだけをオフライン対応 | Aと同じ。圧外で再起動しても開ける | Aと同じ | 高い | 大（専用の Service Worker をそのページにだけ置く） | 0円 |

B を推奨する理由は、圧外で何が起きても写真は iPhone の「写真」に残り、取りこぼしが起きないからです。撮影日時は写真の EXIF から取ります（残留塩素で使っている `src/lib/photoDate.js` を流用）。取込の順序は、①写真を複数選ぶ → ②端末内で元の解像度のままバーコードを読む → ③縮小して送信 → ④メータ・テナントへ自動で割り当て、です。同じメータの写真が2枚あれば新しい方を採用して知らせます。

### 3-2. バーコードの読み取り

- バーコードは **Code39**（メータマスタの「バーコード用管理番号」が `*11-A*` の形）で、中身はメータ番号そのものです。写真には必ず写るとの回答です（Q2）
- iPhone の Safari には標準の読取機能が無いため、オープンソースの ZXing（無償）をアプリに同梱します。外部サービスには送りません
- 画面ショットではバーコードが写真の下側に小さく写っているため、**縮小する前の元画像で読みます**。読めなかった写真だけ、「まだ写真の無いメータ」の候補から手で選びます
- 元の写真数枚（9-4 の U7）で読み取り率を先に確かめます

### 3-3. 音声の読み上げ

現行の入力画面の♩ボタンと同じ動きを、Mac のブラウザに入っている音声合成（Web Speech API。無料・外部通信なし）で作ります。値を保存したときに自動で読み上げ、♩ボタンでも読み直せます。数字は「なな・さん・ご・よん・に」と一桁ずつ読むのを既定にします。

### 3-4. テナントマスタはこのアプリを正にする

備品のテナント一覧（`equipment_tenants`）は、FileMaker「検針記録」のマスター画面にある「タスク管理システムへの同期処理」で送られています。回答（Q6）どおり、移行後はこのアプリのテナント一覧を正にし、同期は止めます。

FileMaker のテナントマスタには42項目あり、今の `equipment_tenants` に無いもののうち、**出力に必要な入居年月日と「初月無料にしない」は列を足します**。代表者・火元責任者・緊急連絡先・セキュリティブロック・収容人数などは検針とは関係しませんが、FileMaker を止めると置き場が無くなるため、扱いを 9-3 の Q13 で確認します。

### 3-5. 既存の作りに合わせる点

| 層 | 方針 |
| --- | --- |
| 画面 | `src/pages/Meter*.jsx`。`docs/ui-standard.md` の部品で組む。入口はヘッダのセクションに「検針」を追加 |
| API | `worker/lib/meter.js` を新設し、そこに閉じる |
| DB | Supabase に新テーブル。service role のみで読み書き（既存方針） |
| 写真 | 既存の非公開バケット `report-photos` に `meter/` の接頭辞で保存。送信前に端末で縮小（`imageResize.js` に検針用の設定を追加） |
| 権限 | 入力は社内（staff/admin）。小泉産業様（owner）には見せない（Q9）。入力者と検証者は同じ人でよく、誰がしたかを記録（Q12） |
| PDF | 写真一覧・お渡し票は自主検査表・修理伝票と同じ html2canvas → jsPDF の作り。xlsx は廃棄物のExcel取込と同じく、脆弱性のあるライブラリを避けて必要な範囲だけ自前で書き出す |

## 4. データモデル（Supabase）

FileMaker のテーブル構成をそのまま引き継ぎます。回答（Q3）どおり集計単位は作らず、**メータごとに「所属テナント（請求先コード）」と「テナント内連番」を持たせます**（出力の「請求先コード\_連番」、例 `73070011_2`）。

| テーブル（仮称） | 移行元（件数） | 主な列 |
| --- | --- | --- |
| `equipment_tenants`（既存・備品と共有） | テナントマスタ（52） | 既存の列＋入居年月日・初月無料にしない |
| `meters` | メータマスタ（69） | メータ番号（＝バーコード）・部屋番号・請求先コード・テナント内連番・階・貸室名・メータシール表記・請求明細補足・検針内容（電気/ガス/水道）・表示順・桁数・有効期限・計測対象・撤去済み・面積（㎡・坪）・外調機按分の有無と比率・外調機メータか |
| `meter_readings` | 検針データ（5,181） | 検針月度・メータ・検針日時・値・値\_2・前月の修正・差分の修正値・備考・その時点の請求先コードと連番・写真・記録者・検証者 |
| `meter_photos` | なし（新規） | 保存キー・サムネイル・撮影日時・読めたバーコード・割り当て先・削除予定日（2年後） |
| `meter_ac_units` | 空調機マスタ（96） | 空調機番号・アドレス番号（例 1:1-00）・割当てメータ番号 |
| `meter_ac_usage` | 空調データ（8,256） | 年月度・空調機番号・昼間電力使用量（Wh）・その時点の割当てメータ |
| `settings`（既存） | コンスタントマスタ | 外調係数40・総面積3,300.07・按分対象面積2,578.28・メールの宛先と件名と本文 |

- **使用量（差分）は列として持たずに計算します。** 式は「当月値 − 前月値」で、当月値の方が小さければ桁数で一周したとみなし「当月値 ＋ 10の桁数乗 − 前月値」（Q5）。「前月の修正」があればそれを前月値に、「修正値」があればそれを差分にします（現行の入力画面と同じ）
- 前月値は「そのメータの直前の検針値」です。ガス・水道も同じ考え方で、月の半ばの検針を翌月度に置きます
- 検針値と空調データには、記録した時点の請求先コード・連番・割当てメータを一緒に保存します。入退去でマスタを直しても、過去の月の出力が変わらないようにするためです（FileMaker も同じ持ち方）
- 移行したデータで 2026年10月度の出力を作り、受け取った「検針データ\_2026年10月分.xlsx」と**全セル一致**することを移行の合格条件にします

| 画面 | URL | 元にする FileMaker 画面 | 変わるところ |

| 写真の取込 | `/meter/:month/photos` | （iPhone アプリからのアップロード）・過不足の確認 | 写真をまとめて選ぶだけ。バーコードで自動割当。写真の無いメータと読めなかった写真を並べて表示 |

| 出力と報告 | `/meter/:month/report` | Excel出力・報告 | 検針データ・修理データの xlsx を作り、そのまま提出メールの下書きへ |
| ガス・水道 | `/meter/:month/gas` | ガス・水道お渡し票・検針票の送付 | お渡し票PDF（テナント様用＋控）、検針票のスキャンPDFを添付したメール下書き |

## 6. 出力

出力は今小泉産業様へ送っているファイルと**名前・形式・列の順番まで同じ**にします。請求書Excelが列の位置で値を拾うためです。

| 出力 | 中身 | 元データ |
| --- | --- | --- |
| 検針データ\_yyyy年mm月分.xlsx | 撤去済みを除く全メータ1行ずつ（2026年10月分は65行）、47列。メータの属性、当月・前月・差分（外調機は2値）、検針日、請求対象期間、空調と外調の計算列 | 検針値・空調データ・マスタ |
| 修理データ\_yyyy年mm月分.xlsx | 修理年月（前月1日）・請求先コード・請求先名・備品ID・備品名・本数合計・設置日の列挙の7列 | 備品の入出庫。テナント設置のみ、無償交換は除く（Q8。既存APIと同じ集計を使う） |
| メータ写真一覧（PDF） | 1ページ8枚、値と撮影日時を重ねる | 写真・検針値 |
| ガス・水道お渡し票（PDF） | メータ検針報告書。テナント様用と控をA4に2枚。今月の検針値・今月と前月の使用量 | さくらのガス・水道 |
| 提出メールの下書き | 宛先・CC・件名「検針データ（2026年10月）」・本文、上の xlsx 2つを添付。送信は手で（Q7） | 定数（コンスタントマスタから移行） |
| ガス検針票のメール下書き | 件名「BKBさくら殿ガス検針票」、スキャンした検針票PDFを添付 | 同上 |

**検針データの計算列について（D1）**

回答（Q4）では「係数以降の計算は請求書作成時に行う」とのことでしたが、受け取った請求書Excelは、FileMaker が計算して出している次の列をそのまま使っています。

| 列（何列目） | FileMaker の計算 | 請求書Excelでの使い道 |
| --- | --- | --- |
| 空調電力使用量\_計（36） | そのメータに割り当てた室内機の昼間電力使用量の合計（Wh） | サマリーのX列 |
| 空調電力使用量\_請求用（37） | 上を 1000 で割って切り捨て（81,598 → 81） | 「空調外調\_合計」の元 |
| 外調機電気量\_当月（39） | 外調機メータの差分＋差分\_2 | サマリー W2 |
| 外調機電気量\_請求用（42） | 外調当月 × 係数40 × 按分比率 | サマリーのW列 |
| 空調外調\_合計（12）、請求先合算（44・45） | 上の合計と、請求先コード×検針内容（電気・ガス・水道）ごとの合算 | サマリーのAE・Y・Z列 |

これらを空欄で出すと、今の請求書Excelでは空調と外調の金額が0になります。計算は単純なので、**今と同じ値をアプリで出し、請求書Excelはそのまま使えるようにするのをおすすめします**。2026年10月分では、受け取った空調データからこの式で計算した値が、出力ファイルの空調（36メータ）と合算の列にすべて一致することを確認しました（外調機は10月は稼働なしで全て0）。

- 現行の写真は 1280×960・平均約290KBです（2026年分、検針データの写真情報より）。このままだと2年で約390MBです。決定（2026-10-20、実写真2枚で確認）: 保存する写真は短辺360px（360×480）・JPEG画質55、1枚約20KB。300×400 だとドラム式メータの回転途中の数字が読みづらくなるため、ここを下限とする。バーコードの読み取りは縮小前の元画像で行う（Q10）

## 10. リスクと触るファイル

最大のリスクは出力ファイルが今と少しでも違うことです。請求書Excelが列の位置で値を拾うため、列が1つずれると請求額が変わります。全セル一致を確かめるまで FileMaker を止めないことで防ぎます。

| リスク | 影響 | 対策 |
| --- | --- | --- |
| 出力xlsxの列・値が今と違う | 請求額が変わる | 10月分（移行データ）、11月分（FileMaker と並行）で全セル一致を確かめる。日付・文字列・数値の型も合わせる |
| 写真からバーコードが読めない | 割り当ての手間が増える | 縮小前の元画像で読む。U7 で先に試す。読めない写真は候補から選ぶだけにする |
| 写真を縮小しすぎて数字が読めない | 検証ができない | U7 で読める限界を確かめて決める。入力画面に拡大を付ける |
| テナント同期の二重管理 | 並行運用中に両方で直すと食い違う | 並行運用中は FileMaker を正のままにし、切替の日に同期を止めてこのアプリへ移す |
| iPhone の写真が HEIC のまま渡る | 取込に失敗する | iPhone から直接取り込むと JPEG に変換される。Mac 経由も実機で確認する |
| 写真はバックアップの対象外 | Supabase 障害時に写真が失われる | 検針値は日次バックアップで守られる。写真は2年で消す前提なので、写真一覧PDFを月ごとに保存する運用で補う |
